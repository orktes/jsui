JSUI 0.7.0 runs JS on its own thread in every native host, as React Native does: frames, animations, scrolling and input keep going while JS renders, commits or collects garbage. It also removes first-launch shader stutter with a pipeline compile pool, precompiles and persistent shader caches.

## Behaviour change: JS on its own thread by default in native hosts

The Godot, Unity and Unreal integrations, the native viewer and the engine examples (raylib, SDL3, sokol) now run the bundle on a JS thread (#112, #114, #115, #118, #120). `jsui_tick` and the renders never wait for JS; each tick applies the React commits JS finished since the last one, whole, and native Animated (host buffers included), scrolling, LayoutAnimations, hit testing, layout and paint run every frame even while JS is busy. With a 300 ms JS stall, Unity kept ticking and rendering with the longest frame under 1 ms.

What changes for a host and an app:

- What JS does in a tick lands in a later tick, unless you wait for it: `jsui_sync(rt, timeout_ms)` or a `jsui_tick_ex` with `JSUI_TICK_SYNC_JS` (scene cuts, screenshots, tests). The integrations expose these as `SyncJs()` / `SyncJsNextFrame()` (Unity, Unreal) and `sync_js()` / `sync_js_next_frame()` (Godot).
- `on_message`, `on_state`, `on_call`, `on_audio`, log and load callbacks run inside a later `jsui_tick` (or `jsui_sync`), not while JS is on the stack; `jsui_post_message` and `jsui_call_ui` only queue.
- `jsui_send_*` return what native predicts, not whether a handler called `preventDefault()`. A key on a view with a key handler waits for JS's answer up to `js_event_deadline_ms` (100 ms by default).
- React Native's callback measures (`ref.measure`, `UIManager.measure`) answer after the next layout, as in React Native; the synchronous native measure reads the last frame's layout.

**To opt out** (single-threaded frames as in 0.6.0): set `jsThread = JsThreadMode.Off` on Unity's `JsuiView`, `JsThread = EJsuiJsThread::Off` on Unreal's `UJsuiWidget`, `js_thread = JS_THREAD_OFF` on Godot's `JsuiView`, or pass `--js-thread off` to the viewer and examples. In the C API the mode is `JsuiConfig.js_thread` / `jsui_set_js_thread`, and `jsui_config_init` still defaults to `JSUI_JS_THREAD_OFF`. `JSUI_JS_THREAD_LOCKSTEP` runs JS on the thread but waits for it every frame, which gives single-threaded frames. The web build is unchanged (the host JS engine has no JS thread; worker mode is still opt-in).

New APIs: `jsui_sync`, `JSUI_TICK_SYNC_JS`, `jsui_debug_stall_js` (demos and smoke tests), `on_js_ready` to wake a sleeping host, and `js_*` perf counters (`js_busy_ms`, `js_lag_frames`, `js_sync_ms`, ...). The viewer switches modes with F6 and stalls JS with F7. The JS-thread suites run under ThreadSanitizer in CI.

## No more first-launch shader stutter

- **Graphite compile pool**: Metal, Vulkan and Dawn contexts compile pipelines on up to 4 background threads, so a frame with several new kinds of draws waits for the slowest compile instead of their sum, and preloaded shaders (`precompileShaders`) warm up off-frame (#113).
- **Pipeline cache by default**: Graphite keeps a cache file per program in the user's cache directory, so pipelines a first launch compiles are ready from the second launch on, in every host (#113).
- **Common precompiles**: the pipelines JSUI's painter draws most (fills, images, gradients, text, blurred rounded rects, for single-sampled and multisampled passes) are precompiled on the first frame of a target, and `jsui_gpu_prepare_target` starts them before the first frame (Godot calls it). `JSUI_PRECOMPILE_COMMON=off` turns it off (#116, #117).
- **Ganesh shader cache file** for GL program binaries, Direct3D HLSL and iOS Metal (#119).

## Rendering and showcase

- **Nine-patch shadow masks** on GPU canvases: a big card's shadow is rendered at its corners plus a stretched middle instead of full size on the CPU, removing a 25 ms paint on the showcase's Home to Motion navigation (#111).
- **Native-first showcase screens**: the scoreboard's match clock, the loading screen's progress and the inventory's hover popouts run on native Animated values, state styles and `Visibility` instead of re-rendering React; the scoreboard's idle JS dropped from 125 to 55 µs per frame (#110).
