JSUI 0.8.0 continues the native-first work on top of 0.7.0's JS thread: input default actions no longer wait for JS, a native typewriter and pausable clocks, an overlay layer for popouts, and a much cheaper render-thread snapshot. A new guide, [docs/NATIVE_FIRST.md](https://github.com/orktes/jsui/blob/main/docs/NATIVE_FIRST.md), says when to use each native-first feature.

## Highlights

- **Input without waiting on JS** (#122): with JS on its own thread, Tab, Enter / Space / gamepad A, D-pad and stick navigation, text editing and wheel scrolling used to wait for JS's answer whenever a listener was on the path. Native now decides from the committed tree:
  - handlers marked `fn.__passive = true` never call `preventDefault()`, so their default action runs at once;
  - `preventDefaultKeys` (key or code) and `preventDefaultButtons` (gamepad buttons) on the focused path veto those keys at once, whatever JS answers;
  - global listeners can veto only some keys: `addGlobalListener(type, fn, { passive } | { vetoes })`.
  Pressable, Touchables, Text, TextInput, Modal, BackHandler and the gamepad store declare these themselves, so Enter presses, focus moves and typing never wait for JS.
- **Native typewriter** (#123): `<Text reveal revealMode="chars|words" revealFade revealFraction>` paints only the first N graphemes or words of a paragraph laid out whole, so it never re-wraps. `Animated.Text reveal={node}` drives it natively. The showcase dialogue's JS time went from 245 to 1.5 µs per frame.
- **Pausable clocks** (#123): `Animated.clock({ start, speed, paused, running })` with `pause()`, `resume()`, `reset(t)` and `setSpeed(x)`, run natively; a `running` node (a host-state bind, an interaction) can hold it. A paused clock no longer keeps the host rendering. `Animated.clock()` without options is still the shared frame clock.
- **Overlay layer for popouts** (#124): `<Overlay anchor placement offset flip collision boundary matchWidth hideWhenClipped>` renders its children above everything and outside any clip, while staying the logical child of its React parent (hover and press chains, groups, focus order, event bubbling). The runtime places it next to its anchor every layout, flips it when it doesn't fit, keeps it inside the viewport or a boundary, and follows scrolling and transforms with no JS. `<OverlayArrow>` points at the anchor.

## Performance

- **Render-thread snapshot** (#125): with the JS thread on, every tick rebuilt the frame snapshot JS reads from (~30 µs and 300-1200 allocations per frame). Unchanged tables are now shared with the last snapshot, an unchanged tick publishes nothing, and empty overlays are skipped: 3-10x less owner-thread work per frame.

## Showcase

- Inventory popouts use the overlay layer: drawn above neighbouring slots and panels, flipped below when there is no room, kept on screen (#124).
- The dialogue typewriter reveals natively (#123).
